# مصفوفة سيناريوهات E2E التشغيلية — منصة مدرسة أزاد

> **الهدف:** تحقق تشغيلي شامل بدورات حياة كاملة (تهيئة ← تشغيل ← تغيير حالة ← تحقق مالي/أكاديمي ← إغلاق).
> **التنفيذ:** `tests/e2e/test_operational_lifecycles.py` — يُنفَّذ في CI ضمن حزمة pytest العادية.
> **البيانات:** أسماء عربية/إنجليزية واقعية، عملة ILS، تواريخ ومدفوعات واقعية.

## النطاق الوظيفي الفعلي للمنصة

| المجال | ما هو موجود فعلاً | ملاحظة |
|---|---|---|
| التينانتس | School جذر التينانتس + user_role_links + RLS | ✅ |
| المدفوعات | manual payments (إيداع/موافقة/رفض)، Stripe/PayTabs/CashU webhooks | ✅ |
| المحاسبة | subscription_balance، فواتير PDF، خصومات، محفظة (تحويلات، عمولات، credit) | ✅ |
| أكاديمي | صفوف/وحدات/دروس/مرفقات، حضور عبر gradebook، اختبارات MCQ/TF/essay مع خلط، تصحيح آلي/يدوي، بطاقة تقارير | ✅ |
| خصوصي | tutor profiles، جلسات، عمولات، مدفوعات، تقييم | ✅ |
| واتساب | webhook + توقيع + أوامر #حضور/#درجات/#اشتراك/#مساعدة + idempotency | ✅ |
| AI | توليد اختبار من درس، RAG، fallback عند quota/offline | ✅ |
| حزم دروس (bundles) | **غير موجودة في المنصة** | يُغطى البديل: محفظة + جلسات بسعر |

## مصفوفة السيناريوهات

| # | السيناريو | المجال | دورة الحياة المغلقة |
|---|---|---|---|
| S1 | تأسيس مدينتين مدرسيتين مستقلتين بكل الأدوار | 1 | إنشاء مدرستين ← مستخدمون بأدوارهم ← روابط أدوار معتمدة ← دخول فعلي لكل دور |
| S2 | عزل التينانتس التشغيلي (كشف التسريب) | 1+7 | طالب من مدرسة A يحاول مسارات مدرسة B: فصل/عرض/درجات/واجبات — 403/404 بلا أي تسريب محتوى |
| S3 | دورة حياة الاشتراك المدفوع كاملة | 2 | خطة 850 ILS ← اشتراك ← دفعتان (500+350) ← موافقة المدير ← اشتراك نشط ← رصيد 0 ← فاتورة PDF |
| S4 | كود الخصم والدفع الزائد | 2 | كود 15% ← تطبيق على اشتراك ← دفع زائد ← الرصيد/الحساب صحيحان |
| S5 | الانتهاء والتجديد | 2 | اشتراك منتهي ← expire-subscriptions ← إعادة اشتراك ← حالة صحيحة |
| S6 | المنهج والحضور والتقارير | 3 | صف بطلاب ← تسجيل حضور (حاضر/متأخر/غائب) ← ملخص الحضور ← بطاقة تقارير |
| S7 | دورة اختبار كاملة (MCQ+TF+Essay) مع الخلط | 3 | اختبار بثلاثة أنواع ← محاولتان تختلفان في الترتيب ← إجابات ← تسليم ← تصحيح آلي للهدف + يدوي للمقالي ← الدرجة النهائية |
| S8 | الدروس الخصوصية والمحفظة والعمولة | 4 | مستخدم فردي ← شحن محفظة 500 ILS ← حجز جلسة 120 ILS ← خصم المحفظة ← عمولة المدرّس ← تقييم الجلسة |
| S9 | واتساب: ربط + أوامر + idempotency | 5 | ربط رقم ← #مساعدة ← #اشتراك ← إعادة إرسال نفس wamid (لا معالجة ثانية) ← إشعار داخلي مُسجَّل |
| S10 | AI: توليد اختبار + fallback عند نفاد الحصة | 6 | توليد اختبار (LLM وهمي) ← استنفاد الحصة ← رفض مهذب دون انهيار |
| S11 | RLS fail-closed على مستوى القاعدة | 7 | بلا GUCs: قراءة جداول التينانتس تُرجع صفراً؛ عبر platform_scope: مرئية؛ bypass يقتصر على super_admin |
| S12 | فاتورة متعددة الدفعات بعملات صحيحة | 2 | اشتراك ← دفعتان بمبالغ مختلفة ← ملخص المدفوعات والرصيد بعد كل دفعة |

## معايير الإغلاق لكل سيناريو

1. كل خطوة تشغيلية عبر الواجهة الحقيقية (test client) أو الخدمة الرسمية (service layer) — لا كتابة قاعدة مباشرة إلا لتهيئة المرجع.
2. تحقق مالي/أكاديمي رقمي دقيق بعد كل تغيير حالة.
3. صفر تسريب بين التينانتس في كل خطوة قراءة.
